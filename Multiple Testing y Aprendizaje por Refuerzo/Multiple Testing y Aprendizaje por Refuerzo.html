A3.3 Multiple testing y aprendizaje por refuerzo
 
1. Introducción

En este trabajo se desarrollan dos tutoriales enfocados en técnicas utilizadas en el análisis de datos y aprendizaje automático. El objetivo es presentar procesos reproducibles que permitan entender el comportamiento de distintos métodos a partir de su aplicación práctica.

El primer tutorial aborda el problema de realizar múltiples pruebas estadísticas sobre datos de alta dimensionalidad y el impacto que esto tiene en la interpretación de resultados. El segundo tutorial se centra en el aprendizaje por refuerzo, mostrando cómo un agente puede mejorar su desempeño mediante la interacción con un entorno.
 
2. Tutorial 1: Multiple Testing

En este tutorial se aborda el problema de realizar múltiples pruebas de hipótesis sobre un mismo conjunto de datos. Cuando se analizan datasets de alta dimensionalidad, como en el caso del dataset NCI60, es común evaluar miles de variables de forma simultánea, lo que incrementa la probabilidad de obtener resultados significativos por azar.

El objetivo de este tutorial es mostrar, mediante un flujo reproducible, cómo identificar variables significativas al comparar dos grupos de datos, y cómo diferentes métodos de corrección permiten controlar el error asociado a múltiples comparaciones. Para ello, se realiza primero una reducción de dimensionalidad con PCA, seguida de un clustering de las observaciones. Posteriormente, se aplican pruebas t para cada variable y se analizan los resultados sin ajuste y con distintos métodos de corrección: Bonferroni, Holm y Benjamini-Hochberg.

A lo largo del proceso, se observa cómo la cantidad de variables significativas cambia dependiendo del método utilizado, lo que permite entender el impacto de cada enfoque en el análisis estadístico.

2.4 Pruebas de hipótesis múltiples con t-test

Ahora se comparan los dos clusters obtenidos en la sección anterior mediante pruebas t independientes. La comparación se realiza variable por variable, es decir, se evalúa si el promedio de cada una de las 6830 variables es diferente entre el cluster 0 y el cluster 1.

Cada prueba genera un p-value, el cual indica qué tan fuerte es la evidencia estadística para afirmar que existe una diferencia entre ambos grupos. Primero se identifican las variables significativas sin aplicar corrección por pruebas múltiples, usando un umbral de p < 0.05. Esta primera revisión sirve como punto de comparación para las correcciones que se aplicarán después.

2.5 Ejemplo conceptual: torneo de monedas

Ahora se simula un torneo de lanzamiento de monedas para representar el problema de las pruebas múltiples. La idea es observar que, cuando muchas personas lanzan una moneda varias veces, pueden aparecer resultados extremos incluso si todas las monedas son justas.

Se simularán 1000 personas, donde cada una lanza una moneda 10 veces. Después se contará cuántas personas obtuvieron 0, 1, 2, ..., 10 caras. Este ejemplo ayuda a entender por qué, al realizar muchas pruebas estadísticas, pueden aparecer resultados aparentemente “significativos” solo por casualidad.

2.6 Control del error tipo I: FWER

En esta sección se aplica el control del Family-Wise Error Rate (FWER), cuyo objetivo es reducir la probabilidad de cometer al menos un falso positivo cuando se realizan muchas pruebas al mismo tiempo.

Para esto se usarán dos métodos de ajuste de p-values:

- Bonferroni, que es un método conservador y ajusta los p-values multiplicándolos por el número total de pruebas.

- Holm, que también controla el FWER, pero suele ser menos restrictivo que Bonferroni porque ajusta los p-values tomando en cuenta su orden.

Ambos métodos se aplicarán a los p-values obtenidos en las pruebas t de la sección anterior.
In [13]:
from statsmodels.stats.multitest import multipletests

alpha = 0.05

# Ajuste Bonferroni
rechazo_bonf, pvals_bonf, _, _ = multipletests(

    alpha=alpha,
    method="bonferroni"
)

# Ajuste Holm
rechazo_holm, pvals_holm, _, _ = multipletests(

2.7 Control de descubrimientos falsos: FDR

Por último, se aplica el método Benjamini-Hochberg para controlar el False Discovery Rate (FDR). A diferencia del FWER, que busca reducir la probabilidad de cometer al menos un falso positivo, el FDR controla la proporción esperada de falsos positivos dentro del conjunto de resultados significativos.

Este método suele ser menos restrictivo que Bonferroni y Holm, por lo que puede conservar más variables significativas. En este caso se utiliza un nivel de q = 0.01, es decir, se busca controlar la tasa de descubrimientos falsos al 1%.

3. Tutorial 2: Reinforcement Learning

En este tutorial se aborda el aprendizaje por refuerzo mediante la implementación de un agente basado en Q-learning en el entorno CartPole. A diferencia de los métodos tradicionales de aprendizaje supervisado, en este caso el agente aprende a partir de la interacción directa con el entorno, recibiendo recompensas en función de sus acciones.

El objetivo es entrenar un agente capaz de mantener el equilibrio de un poste sobre un carro durante el mayor tiempo posible. Para ello, se comienza explorando el entorno y evaluando el desempeño de un agente aleatorio, lo que permite establecer una referencia inicial. Posteriormente, se discretiza el espacio de estados, se construye una Q-table y se entrena el agente utilizando una estrategia ε-greedy.

A lo largo del proceso, se analiza cómo el agente mejora su desempeño conforme aprende, comparando sus resultados con los obtenidos inicialmente. Finalmente, se evalúa el agente entrenado para observar su comportamiento y validar la efectividad del aprendizaje.

3.5 Preparación para Q-learning

En esta sección se prepara el entorno para aplicar Q-learning. Debido a que el espacio de estados del problema es continuo, primero es necesario discretizarlo, es decir, convertir cada variable en intervalos (bins) para poder construir una Q-table.

Se definen límites para cada variable del estado y una cantidad de bins por dimensión. Posteriormente, se implementa una función que transforma cada observación en una tupla de índices discretos. Finalmente, se inicializa la Q-table y se establecen los hiperparámetros del algoritmo.
In [32]:
import numpy as np

# ============================
# 1. Definir límites del estado
# ============================
limites = [
    (-2.4, 2.4),   # posición
    (-0.5, 0.5),   # velocidad
    (-0.2, 0.2),   # ángulo
    (-2, 2)        # velocidad angular
]

# ============================
# 2. Definir número de bins
# ============================
bins = [1, 1, 6, 12]

# Crear discretización para cada dimensión
bins_arrays = [
    np.linspace(limites[i][0], limites[i][1], bins[i] - 1)
    for i in range(len(bins))
]

# ============================
# 3. Función de discretización
# ============================
def discretizar_estado(obs):
    estado_discreto = []
    for i in range(len(obs)):
        valor = obs[i]
        limites_i = limites[i]

        # Limitar valores fuera de rango
        valor = max(limites_i[0], min(limites_i[1], valor))

        # Encontrar índice del bin
        bin_index = np.digitize(valor, bins_arrays[i])
        estado_discreto.append(bin_index)

    return tuple(estado_discreto)

# ============================
# 4. Inicializar Q-table
# ============================
estado_ejemplo = discretizar_estado(obs)

print("Ejemplo de estado continuo:", obs)
print("Estado discretizado:", estado_ejemplo)

# Crear Q-table
q_table = np.zeros(bins + [env.action_space.n])

print("Dimensiones de la Q-table:", q_table.shape)

3.6 Entrenamiento con ε-greedy (Q-learning)

Después de la preparación, se entrena un agente mediante Q-learning utilizando una estrategia ε-greedy. En cada paso, el agente decide entre explorar una acción aleatoria o explotar la mejor acción conocida en la Q-table.

Durante el entrenamiento, la Q-table se actualiza con base en la recompensa recibida y en el mejor valor esperado del siguiente estado. Además, el valor de epsilon disminuye gradualmente para que el agente explore mucho al inicio y dependa más de lo aprendido conforme avanza el entrenamiento.
In [36]:
# Lista para guardar la recompensa de cada episodio
recompensas_entrenamiento = []

for episodio in range(n_episodios):
    obs, info = env.reset()
    estado = discretizar_estado(obs)

    recompensa_total = 0

    for paso in range(max_pasos):
        # Selección de acción con estrategia epsilon-greedy
        if np.random.random() < epsilon:
            action = env.action_space.sample()  # explorar
        else:
            action = np.argmax(q_table[estado])  # explotar

        # Ejecutar acción
        nueva_obs, reward, terminated, truncated, info = env.step(action)
        nuevo_estado = discretizar_estado(nueva_obs)

        # Actualizar Q-table
        mejor_q_siguiente = np.max(q_table[nuevo_estado])
        q_actual = q_table[estado + (action,)]

        q_table[estado + (action,)] = q_actual + learning_rate * (
            reward + gamma * mejor_q_siguiente - q_actual
        )

        estado = nuevo_estado
        recompensa_total += reward

        if terminated or truncated:
            break

    # Reducir epsilon
    epsilon = max(epsilon_min, epsilon * epsilon_decay)

    # Guardar recompensa del episodio
    recompensas_entrenamiento.append(recompensa_total)

print("Entrenamiento finalizado")
print("Recompensa promedio final (últimos 100 episodios):", np.mean(recompensas_entrenamiento[-100:]))
print("Recompensa máxima durante entrenamiento:", np.max(recompensas_entrenamiento))
print("Epsilon final:", epsilon)
